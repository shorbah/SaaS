# Git والبيئات والفرض الآلي

## 1. سير العمل

- في المستودعات المشتركة أو التغييرات غير البسيطة، استخدم فرعاً للمهمة (`feat/…`, `fix/…`) ولا تعدّل `main` مباشرة. في مشروع محلي تجريبي وتعديل L0 بسيط، لا تفرض إنشاء فرع إذا كان ذلك يضيف عبئاً بلا فائدة.
- commits صغيرة برسائل واضحة. أنشئ **نقطة استرجاع** (commit) قبل أي تغيير واسع.
- لا `push --force`. لا تعديل لتاريخ مشترك.
- لا تدفع إلى `main` ولا تنشر للإنتاج. المطور يراجع ويدمج.
- PR: وصف، ما تغيّر، ما اختُبر، المخاطر، خطة التراجع.

## 2. البيئات

| البيئة | الغرض | وصول الوكيل |
|:---|:---|:---|
| local | تطوير | نعم |
| preview/staging | مراجعة | محدود، بموافقة |
| production | مستخدمون حقيقيون | **لا** بيانات اعتماد |

- ملفات إعداد منفصلة لكل بيئة، بلا أسرار في المستودع.
- لا تُشغّل الوكيل بحساب له صلاحيات الإنتاج.

## 3. الفرض الآلي (لا تعتمد على النص وحده)

اقترح على المطور تفعيل ما يلي وساعده في إعداده:

| الطبقة | الأداة |
|:---|:---|
| صلاحيات تنفيذ الطرفية للوكيل | قوائم السماح/المنع في إعدادات الوكيل (امنع `rm -rf`, `git push --force`, `git reset --hard`, أوامر DB التدميرية) — راجع توثيق الأداة الحالي |
| قبل الـ commit | gitleaks، formatter، lint، typecheck |
| CI | lint + typecheck + tests + فحص أسرار + فحص ثغرات الاعتماديات + build |
| حماية الفرع | منع الدفع المباشر لـ `main`، مراجعة إلزامية، CI ناجح |
| حدود الهيكل | ESLint `no-restricted-imports` أو eslint-plugin-boundaries أو dependency-cruiser |
| قاعدة البيانات | نسخ احتياطية دورية/PITR، وحساب خدمة للتطبيق بأقل صلاحيات |

- **حتمية التحقق في CI ومنع تعارض الوكلاء (CI Enforcement & Concurrency):**
  - الخطافات المحلية (`Git Hooks`) هي خط دفاع أول فقط (لإمكانية تجاوزها بـ `--no-verify`). الحاجز الأمني الإلزامي هو فحص الـ CI المرتبط بنفس بصمة الـ Commit والنسخة النهائية المراد دمجها عبر `Required Status Checks`.
  - عند تشغيل أكثر من وكيل بالتزامن (Multi-Agent Execution)، يُمنع عمل وكيلين على نفس نطاق الملفات (`allowed_paths`) في نفس الفرع؛ يُعزل كل وكيل في فرع/شجرة عمل مستقلة (`Git Worktree`) مع التحقق من `base_commit` وإعادة فحص المطابقة الشاملة بعد الدمج.

## 4. إعداد AGENTS.md

اجعله قصيراً (10–15 سطراً) ويشير للمهارة بدل نسخ قواعدها (تكرار القواعد يسبب انحرافاً بين النسخ). الكتلة الموصى بها في `README.md` أدناه.
