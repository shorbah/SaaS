# الهيكل وعزل الميزات وأنواع المشاريع

## 0. الأسبقية

**اتبع بنية المشروع القائمة أولاً.** ما يلي افتراضات للمشاريع الجديدة أو عند طلب إعادة الهيكلة.

## 1. عزل الميزات

كل ميزة ذات منطق/واجهة مستقلة تعيش في شريحة واحدة بواجهة عامة واحدة. مثال (TypeScript):

```
src/features/<name>/
├── index.ts        # الواجهة العامة الوحيدة
├── components/  hooks/  services/
├── types.ts
└── __tests__/
```

للميزة الصغيرة: `index.ts` + `__tests__/` فقط. لا تنشئ مجلدات فارغة.

**الحدود:**
- ✅ استيراد من `@/features/<name>` (index) ومن `shared/` فقط.
- ❌ استيراد عميق من ملفات داخلية لميزة أخرى.
- إن احتاجت ميزة شيئاً من أخرى: صدّره صراحة من `index.ts` أو انقله إلى `shared/`.
- فضّل التصدير الصريح (`export { X } from './X'`) على `export *` لتجنب تضخم الحزم.
- المكوّن الذي تستخدمه صفحة واحدة يبقى مع صفحته. تغيير سطرين لا يحتاج شريحة.
- **افرض الحدود بأداة** (انظر `git-and-environments.md`)، فالنص وحده لا يكفي.

## 2. أنواع المشاريع (يمكن دمجها)

### تطبيق ويب كامل (Full-stack)
- عزل الميزات + `security.md` + `data-and-migrations.md`.
- تصميم متجاوب. لغة الواجهة واتجاهها (RTL/LTR) **إعداد للمشروع** يُحدَّد في `DESIGN.md`.
- هرم الحالة: `URL` ← حالة المكوّن المحلية ← كاش الخادم ← مخزن الواجهة العام (لا يكون مصدراً وحيداً لبيانات الخادم).

### تطبيق جوال/سطح مكتب
- تخزين الرموز في مخزن النظام الآمن (Keychain/Keystore/SecureStore).
- المساحات الآمنة، الروابط العميقة، الوضع غير المتصل، والتحديثات الهوائية دون كسر الإصدار الثنائي.
- هرم الحالة: التنقل ← حالة الشاشة ← كاش الخادم/الأوفلاين ← مخزن عام.
- لا أسرار داخل التطبيق: كل ما في الحزمة يمكن استخراجه.

### خدمة خلفية / API
- مخططات تحقق عند كل endpoint، فصل منطق الأعمال عن طبقة النقل.
- تحديد معدل الطلبات، سجلات منظّمة بلا أسرار.
- حذف منطقي، وفحص الملكية في كل مورد.

### مكتبة / أداة CLI
- واجهة عامة صغيرة، اعتماديات قليلة، تغطية اختبارات أعلى (يستخدمها غيرك)، توافق عبر الأنظمة، وإصدارات دلالية (semver).

### موقع عام / توثيق
- Core Web Vitals، إتاحة، SEO.
- إن جمع بيانات زوار (نماذج، تحليلات، كوكيز): إشعار وموافقة.
