## 🛑 هل تثق في وكيل الذكاء الاصطناعي بنسبة 100%؟

### أسئلة يعاني منها كل مبرمج يستخدم الذكاء الاصطناعي اليوم:

#### ❓ س1: طلبت تعديل لون زر أو نص بسيط، فقام الوكيل بتعديل 12 ملفاً وخرب معمارية مشروعك بالكامل؟
> **الحل في Master Foundation:**  
> **مصفوفة المخاطر وقفل النطاق الصارم (Risk Matrix & Floor Rule):** المهارة تجبر الوكيل على تصنيف المهمة لحظياً (L0 إلى L3). التعديل البسيط (L0/L1) مقيد بملف أو دالة واحدة، وفي المهام الكبيرة (L3) يتم حظر الوكيل ميكانيكياً من لمس أي ملف خارج النطاق المعتمد مشفّراً (`allowed_paths`).

#### ❓ س2: كم مرة مسح الوكيل بيانات قاعدة البيانات (`DROP TABLE`) أو نفّذ `git reset --hard` وضاعت ساعات من عملك؟
> **الحل في Master Foundation:**  
> **الخط الأحمر الأول (Zero Data Destruction):** حظر قطعي لأي عملية تدميرية غير قابلة للتراجع دون موافقة كتابية صريحة مسبقة تعرض الأثر بالتفصيل. لا يمكن للوكيل تجاوز هذا الخط مهما حاولت الـ Prompts خداعه.

#### ❓ س3: يخبرك الوكيل بثقة عمياء: *"تم تنفيذ الميزة والاختبارات تعمل 100%"*، ثم تشغّل المشروع لتجده منهاراً تماماً؟
> **الحل في Master Foundation:**  
> **مبدأ الحقيقة بالأدلة (Evidence Before Assertions):** يمنع الوكيل منعاً باتاً من ادعاء النجاح أو كتابة تقرير إنجاز ما لم يُشغّل الفحوصات فعلياً (Build, Tests, Lint) ويعرض مخرجاتها الحقيقية نصاً في الشات أمامك.

#### ❓ س4: هل تقلق من أن يقرأ الوكيل ملف `.env` ويسرب مفاتيح الـ API أو أسرار السيرفر؟
> **الحل في Master Foundation:**  
> **حراسة الأسرار الصارمة (Secret Hygiene):** تمنع المهارة قراءة أو طباعة أو تمرير قيم المتغيرات البيئية؛ يُسمح للوكيل فقط بالتحقق من **وجود المتغير** دون معرفة قيمته السرية.

#### ❓ س5: هل سئمت من المهارات الضخمة التي تحشو 500 سطر في الذاكرة وتلتهم الـ Tokens وتجعل الوكيل بطيئاً ومشتتاً؟
> **الحل في Master Foundation:**  
> **معمارية العمود الفقري (Spine Architecture):** ملف التوجيه الرئيسي حجمه **102 سطر فقط**! يقود الوكيل بدقة متناهية ولا يستدعي المراجع التفصيلية المتخصصة إلا عند الحاجة إليها فعلياً، مما يوفر 80% من استهلاك التوكنز ويحافظ على أقصى تركيز للنموذج.

### 👥 كيف تُغيّر هذه المهارة تجربة العمل بحسب مستواك؟

#### 🔰 أولاً: بعين المبتدئ ورواد الأعمال (Vibe Coders & Beginners)
> *"أريد بناء فكرتي بسرعة، لكنني أخشى أن يكتب الذكاء الاصطناعي أكواداً مبعثرة لا أفهم كيف أصلحها، أو يرتكب خطأً كارثياً يدمر مشروعي."*

* **درع أمان تلقائي (Seatbelt & Airbag):** لا تحتاج لمعرفة كافة خفايا الأمان؛ المهارة تعمل كحارس خفي يمنع الوكيل من مسح الجداول أو كسر الاعتماديات أو تسريب الأسرار نيابة عنك.
* **البساطة التامة (تحكم بكلمة واحدة):** قبل أن يغير الوكيل أي شيء، يشرح لك في 3 أسطر واضحة ما سيفعله بالضبط، ويتوقف تماماً حتى تكتب له: **"نفّذ"**. أنت دائماً صاحب القرار.
* **جودة محترفة تلقائياً (Clean Code & Tests):** تجبر المهارة الوكيل على كتابة كود نظيف وتوليد اختبارات ذات معنى، فلا ينتهي بك المطاف بـ "سباغيتي كود" يعجز أي مطور لاحقاً عن صيانته.

#### ⚡ ثانياً: بعين المطور المحترف وقادة الفرق (Senior Engineers & Architects)
> *"الذكاء الاصطناعي رائع كأداة تسريع، لكن عدم قابليته للتنبؤ (Non-Deterministic Behavior) وانحرافه عن المعمارية (Drift) يجعله خطراً على بيئات الإنتاج ومراجعات الـ PR."*

* **الحراسة المشفرة ضد الانحراف (Cryptographic Spec Gate & Anti-Drift):**  
  في التغييرات المعمارية (L3)، لا يتم قبول أي كود إلا بوجود ملف اعتماد رقمي `APPROVAL.json` موقع بمفتاح **Ed25519** وبصمة **RFC 8785 Canonical JSON**. إذا انحرف الوكيل وعدل ملفاً غير مصرح به، يرفضه خطاف الـ Git محلياً وتسقطه الـ CI في GitHub Actions فوراً.
* **الفصل الحاسم بين الكود والتشغيل (Local Code vs Operational Infrastructure):**  
  اعتمادك لخطة برمجية يمنح الوكيل حق كتابة واختبار الكود محلياً فقط. تطبيق ترحيلات لقواعد بيانات سحابية، أو تنفيذ معاملات مالية، أو تشغيل أوامر سحابية يتطلب **تفويضاً تشغيلياً مستقلاً (Operational Approval)** عند لحظة التنفيذ.
* **جاهزية الإنتاج والامتثال (Zero-Trust AI):**  
  المهارة تعامل أي محتوى خارجي (Web, PRs, Issues, MCP) على أنه **بيانات غير موثوقة وليست أوامر**، مما يغلق ثغرات الـ Prompt Injection وسلسلة التوريد تماماً.

## 🚀 التثبيت والتهيئة السريعة

مسارات المهارات تختلف بين الأدوات وإصداراتها. **راجع توثيق أداتك الحالي** قبل اعتماد أي مسار.

### الطريقة الموصى بها (سكربت الإعداد الشامل بنقرة واحدة):
```powershell
git clone https://github.com/shorbah/SaaS.git
cd SaaS
powershell -ExecutionPolicy Bypass -File .\scripts\setup-device.ps1
```
*يتكفل السكربت بربط خطافات Git، وتوليد المفتاح الرقمي Ed25519، وتوزيع المهارات عالمياً لكافة الـ IDEs، وتشغيل 29 فحص تحقق آلي.*

### أو التثبيت اليدوي لمجلد المهارة:
```bash
# استنساخ المستودع ونسخ مجلد المهارة
git clone https://github.com/shorbah/SaaS.git

# مسار Antigravity العام:
# ~/.gemini/config/skills/master-foundation

# مسار Claude Code العام:
# ~/.claude/skills/master-foundation

# مسار المشروع المحلي:
# .agents/skills/master-foundation
```

نصائح مهمة:
- ثبّت على **tag أو commit محدد** وليس على آخر إصدار تلقائياً في بيئات الإنتاج.
- راجع أي مهارة طرف ثالث قبل تفعيلها لحماية سلسلة التوريد.

# Master Foundation (v6.5)
ابدأ كل مهمة برمجية أو معمارية بمهارة `master-foundation`: صنّف المخاطرة (L0–L3/AUDIT) ثم اتبع المراجع المناسبة.

2. توقف وانتظر كلمة "نفّذ" مني. لا تعدّل أي شيء قبلها (مسموح دون انتظار: الإجابة عن الأسئلة، قراءة الملفات، والبحث).
